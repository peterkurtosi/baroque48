On the machine this is a command: MODE GREEN. The phosphors are the real ones — P3 amber, P1 green, P4 white.

What it is

A small computer that boots into BASIC, keeps its programs on floppies you can hold, and screeches like a tape deck when it loads them. It has its own DOS-like shell and file manager — ours, written for this machine, not an emulation of anyone else's.

It runs on an ESP32-S3 with a 7″ 800×480 panel, 16 MB of flash and 8 MB of PSRAM.

Why 48

The machine has 8 MB of memory. BASIC gets 49 152 bytes of it.

That is not nostalgia and it is not a joke. It is a promise: whatever you write here will fit on a real 48K machine. The number in the name is a compatibility guarantee, and it is why the limit is the product rather than a shortage.

The figure on the boot screen is measured, not printed: the machine writes a changing pattern to every byte of that workspace, reads it back, and counts the good ones. If one byte failed, the number would be smaller.

The abundance goes into how many programs, never into how big any one of them is. What those machines taught was not the memory — it was that a child could LIST a game and change it. Nobody lists a four-megabyte game.

On real hardware

Where we are

Working, measured, on the bench:

  • the boot screen, on a real 7″ panel
  • three phosphor modes, switchable
  • the 48 K workspace, verified byte by byte at power-on
  • an I²S amplifier on the board, ready for the tape sound

Not there yet — and that is most of it:

  • the DOS-like shell and the file manager
  • BASIC
  • the tape-loading sound — the experiment that decides the project
  • the floppies, the case, the keyboard

This page exists because a hundred people said they wanted one before a single line of it was written. It seemed only fair to show them exactly how far along it really is.
